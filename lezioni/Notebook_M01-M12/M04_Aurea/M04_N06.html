1. Almeno un successo

Il complemento di almeno un successo è nessun successo. Questa formulazione evita di sommare dieci termini e rende evidente il legame fra un evento semplice e la sua regione complementare.

R · codice commentato
n <- 10
p <- .30
k <- 0:n
massa <- dbinom(k, n, p)
# Il complemento di almeno un successo e il solo esito zero.
almeno_uno <- 1 - dbinom(0, n, p)
somma_positivi <- sum(massa[k >= 1])
print(c(almeno_uno = almeno_uno, somma_positivi = somma_positivi))
stopifnot(abs(almeno_uno - somma_positivi) < 1e-12)
Risultato dell’esecuzione
almeno_uno somma_positivi 
      0.971752       0.971752

Lettura del risultato

Il complemento funziona perché zero e almeno uno coprono tutti gli esiti possibili e non si sovrappongono. La probabilità di nessun successo non è uno meno dieci volte p: le prove richiedono la regola del prodotto.

2. Una coda discreta

Almeno quattro comprende quattro e tutti i conteggi superiori. pbinom con soglia tre e lower.tail = FALSE calcola direttamente questa coda, evitando ambiguità sul valore di confine.

R · codice commentato
# lower.tail = FALSE con soglia tre include il valore quattro.
almeno_quattro <- pbinom(3, n, p, lower.tail = FALSE)
somma_coda <- sum(massa[k >= 4])
oltre_quattro <- pbinom(4, n, p, lower.tail = FALSE)
print(c(almeno4 = almeno_quattro, oltre4 = oltre_quattro,
        esattamente4 = dbinom(4, n, p)))
stopifnot(abs(almeno_quattro - somma_coda) < 1e-12)
stopifnot(abs(almeno_quattro - oltre_quattro - dbinom(4, n, p)) < 1e-12)
Risultato dell’esecuzione
almeno4       oltre4 esattamente4 
    0.350389     0.150268     0.200121

Lettura del risultato

La differenza fra almeno quattro e più di quattro è tutta concentrata nell’esito quattro. Questo controllo locale è utile quando la frase della consegna contiene parole facilmente confuse.

3. Un intervallo di conteggi

Per includere da due a cinque successi sottraiamo alla cumulativa fino a cinque quella fino a uno. La regione esterna comprende invece meno di due oppure più di cinque; le due code sono disgiunte.

R · codice commentato
# Sottraiamo fino a uno per conservare il bordo inferiore due.
fra_due_e_cinque <- pbinom(5, n, p) - pbinom(1, n, p)
esterno <- pbinom(1, n, p) + pbinom(5, n, p, lower.tail = FALSE)
print(c(interno = fra_due_e_cinque, esterno = esterno))
stopifnot(abs(fra_due_e_cinque + esterno - 1) < 1e-12)
colori <- ifelse(k >= 2 & k <= 5, "#C57E42", "#1D7890")
barplot(massa, names.arg = k, col = colori, xlab = "Successi (k)",
        ylab = "Probabilita", main = "Evento: da due a cinque inclusi")
Risultato dell’esecuzione
interno  esterno 
0.803343 0.196657

Lettura del risultato

Il grafico evidenzia gli esiti la cui probabilità entra nella somma. Le barre rappresentano masse discrete: la probabilità dell’evento è la somma delle altezze selezionate, non l’area di una densità continua.

Variante svolta

Calcolare la probabilità dell’unione ‘al massimo uno oppure almeno otto’ e verificarla con una somma diretta.

R · codice commentato
unione <- pbinom(1, n, p) + pbinom(7, n, p, lower.tail = FALSE)
selezionati <- k <= 1 | k >= 8
controllo <- sum(massa[selezionati])
print(data.frame(k = k, incluso = selezionati))
print(c(unione = unione, somma = controllo))
stopifnot(abs(unione - controllo) < 1e-12)

Le due code non si sovrappongono e si possono sommare direttamente. Per eventi sovrapposti bisognerebbe sottrarre l’intersezione, altrimenti alcuni esiti verrebbero contati due volte.

Errore da riconoscere

Non sommare probabilità di eventi sovrapposti senza correggere il doppio conteggio. Nelle distribuzioni discrete verificare sempre se il bordo inferiore viene incluso o escluso dalla cumulativa sottratta.

Risposta alla domanda

La traduzione dell’evento precede la scelta della funzione. Una somma sugli esiti possibili fornisce un controllo indipendente di cumulative e complementi, soprattutto per soglie e intervalli con estremi inclusi.
