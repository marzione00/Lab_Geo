Come stimiamo un p-value quando non possiamo enumerare tutte le assegnazioni dei fossili ai gruppi?

1. Preparare il contrasto osservato

Manteniamo il verso Spiky meno Rounded e la numerosità originale di ciascun gruppo. La distribuzione nulla per permutazione viene costruita dai valori uniti. Il suo uso richiede una nulla che renda le etichette scambiabili; la sola uguaglianza delle medie non basta in generale.

R · codice commentato
dati <- carica_dati("fossili_simulati.csv")
a <- dati$diametro_tot_um[dati$morfotipo == "Rounded"]
b <- dati$diametro_tot_um[dati$morfotipo == "Spiky"]
x <- c(a, b)
nA <- length(a)
nB <- length(b)
osservato <- mean(b) - mean(a)
stopifnot(all(is.finite(x)))
print(c(nA = nA, nB = nB, differenza_um = osservato))

Lettura del risultato

Le numerosità indicano quante unità sperimentali osserviamo. Non sono il numero di permutazioni e non cambieranno quando aumenteremo la precisione del calcolo.

2. Simulare assegnazioni con numerosità fisse

In ogni replica una selezione senza reinserimento determina il gruppo Rounded sotto la nulla. Tutti gli altri valori formano Spiky. Le permutazioni possono ripetersi fra repliche, mentre ogni assegnazione usa ciascun valore una sola volta.

R · codice commentato
set.seed(604)
B <- 2000
nulli <- replicate(B, {
  iA <- sample.int(length(x), nA, replace = FALSE)
  mean(x[-iA]) - mean(x[iA])
})
print(c(B = B, media_nulla = mean(nulli), SD_nulla = sd(nulli)))
print(quantile(nulli, c(0.025, 0.5, 0.975)))
stopifnot(length(nulli) == B)
Risultato dell’esecuzione

Lettura del risultato

Il centro è vicino a zero sotto riassegnazione casuale. La distribuzione simulata serve a valutare estremi sotto il riferimento nullo, non a costruire direttamente un intervallo del contrasto osservato.

3. Contare le code e calcolare il p-value

Per un confronto bilaterale contiamo i contrasti il cui valore assoluto è almeno quello osservato. Usiamo (k+1)/(B+1), che include il contributo dell’osservazione e impedisce di dichiarare p uguale a zero quando nessuna replica simulata supera la soglia.

R · codice commentato
k <- sum(abs(nulli) >= abs(osservato))
p_mc <- (k + 1) / (B + 1)
minimo <- 1 / (B + 1)
coda_binomiale <- binom.test(k, B)$conf.int
print(c(estremi = k, B = B, p_MC = p_mc, minimo_risolubile = minimo))
print(coda_binomiale)
stopifnot(p_mc >= minimo, p_mc <= 1)
Risultato dell’esecuzione
estremi                 B              p_MC minimo_risolubile 
       0.0000e+00        2.0000e+03        4.9975e-04        4.9975e-04 
[1] 0.00000000 0.00184274

[1] 0.95

Lettura del risultato

L’intervallo binomiale riguarda la probabilità di coda della simulazione, non il parametro biologico. Un p-value piccolo esprime incompatibilità con il riferimento nullo, senza misurare la dimensione dell’effetto.

Variante svolta

Ripetere con tremila permutazioni e un seme diverso, conservando lo stesso campione.

R · codice commentato
set.seed(1604)
B2 <- 3000
nulli2 <- replicate(B2, {
  iA <- sample.int(length(x), nA, FALSE)
  mean(x[-iA]) - mean(x[iA])
})
k2 <- sum(abs(nulli2) >= abs(osservato))
print(data.frame(B = c(B, B2), estremi = c(k, k2),
  p_MC = c(p_mc, (k2 + 1) / (B2 + 1))))
Risultato dell’esecuzione
B estremi        p_MC
1 2000       0 0.000499750
2 3000       1 0.000666445

La differenza fra i risultati riflette errore Monte Carlo e risoluzione. Non è richiesto che il p-value diminuisca quando aumenta B, né che i due valori coincidano.

Errore da riconoscere

Non interpretare zero superamenti come impossibilità dell’evento sotto la nulla. Registrare k e B e usare una formula adatta al campionamento delle permutazioni.

Risposta alla domanda

Il p-value Monte Carlo richiede ipotesi di scambiabilità, statistica e regola di coda esplicite. Più permutazioni stabilizzano il calcolo senza aggiungere osservazioni.
