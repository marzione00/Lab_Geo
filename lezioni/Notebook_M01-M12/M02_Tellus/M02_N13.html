1. Definire un vocabolario di categorie

La normalizzazione deve essere limitata a trasformazioni che non cambiano il significato. Eliminiamo spazi esterni e differenze fra maiuscole e minuscole, poi confrontiamo il risultato con un vocabolario dichiarato: categorie sconosciute restano segnalate.

R · codice commentato
# Conservare anche stringhe vuote e codici testuali prima di interpretarli.
raw <- carica_dati("fossili_da_controllare.csv", sep = ";",
                   colClasses = "character", na.strings = character(),
                   stringsAsFactors = FALSE)
stopifnot(nrow(raw) == 25L)

normalizzate <- tolower(trimws(raw$morfotipo))
vocabolario <- c(rounded = "Rounded", spiky = "Spiky")
categoria <- unname(vocabolario[normalizzate])
sconosciuta <- is.na(categoria)
print(data.frame(originale = raw$morfotipo, normalizzata = categoria))
print(table(categoria, useNA = "ifany"))
stopifnot(!any(sconosciuta))

2. Separare duplicati esatti e chiavi ripetute

Un duplicato esatto confronta tutte le celle originali. Un ID ripetuto confronta invece soltanto la chiave e potrebbe accompagnare misure differenti. Calcoliamo entrambi gli indicatori, includendo tutte le occorrenze degli ID da verificare.

R · codice commentato
duplicato_esatto <- duplicated(raw)
id_ripetuto <- duplicated(raw$id) | duplicated(raw$id, fromLast = TRUE)
audit <- data.frame(riga = seq_len(nrow(raw)), id = raw$id,
                    duplicato_esatto = duplicato_esatto, id_ripetuto = id_ripetuto)
print(audit[id_ripetuto | duplicato_esatto, ])
print(c(record = nrow(raw), ID_distinti = length(unique(raw$id)),
        copie_esatte_successive = sum(duplicato_esatto)))

Lettura del risultato

duplicated marca come copia esatta l’occorrenza successiva, lasciando una prima riga di riferimento. Per l’ID ripetuto mostriamo entrambe le righe, così la revisione può stabilire se si tratti di copia, replica autorizzata o conflitto.

3. Applicare una decisione documentata

Per questa esercitazione creiamo una vista che conserva la prima copia delle righe esattamente identiche. La tabella completa e l’audit rimangono disponibili. Non estendiamo automaticamente la stessa decisione a ogni ID ripetuto con contenuto diverso.

R · codice commentato
vista_unica <- raw[!duplicato_esatto, , drop = FALSE]
print(c(prima = nrow(raw), dopo_copie_esatte = nrow(vista_unica)))
stopifnot(nrow(vista_unica) + sum(duplicato_esatto) == nrow(raw))
stopifnot(!anyDuplicated(vista_unica$id))
write.csv(audit, percorso_risultati("audit_duplicati.csv"), row.names = FALSE)
print(vista_unica[vista_unica$id == "F007", ])

Costruire un conflitto di ID cambiando una misura nella copia di F007.

conflitto <- raw
ultima <- which(conflitto$id == "F007")[2]
conflitto$diametro_tot_um[ultima] <- "7.00"
stesso_id <- duplicated(conflitto$id) | duplicated(conflitto$id, fromLast = TRUE)
print(conflitto[stesso_id, ])
print(c(duplicati_esatti = sum(duplicated(conflitto)), righe_ID_ripetuto = sum(stesso_id)))

La chiave resta ripetuta ma le righe non sono più identiche. Se il protocollo prevedesse repliche, servirebbe un identificativo di replica; altrimenti si dovrebbe verificare quale record appartenga realmente al fossile.

Errore da riconoscere

Eliminare duplicati includendo una nuova colonna riga_origine impedisce di trovare copie identiche, perché la traccia è sempre diversa. Il confronto esatto deve usare le colonne originali pertinenti.

Risposta alla domanda

Categorie e duplicazioni sono controlli distinti con regole esplicite. Normalizzare il testo non decide quali record rappresentino la stessa osservazione; chiavi e contenuto devono essere valutati insieme.
