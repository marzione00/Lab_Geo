1. Scrivere un dizionario essenziale

Il dizionario spiega che cosa rappresenta ogni colonna e in quale unità viene interpretata. Non basta elencare i nomi: identificativi, categorie e misure richiedono descrizioni diverse, specialmente quando la tabella viene letta fuori dal notebook.

R · codice commentato
# Ogni esecuzione riparte dal CSV condiviso, senza modificare il file.
d <- carica_dati("campioni_modulo1.csv", stringsAsFactors = FALSE)
stopifnot(nrow(d) == 24L, !anyDuplicated(d$id))

dizionario <- data.frame(
  campo = c("id", "affioramento", "stazione", "massa_g", "volume_cm3", "alterazione"),
  significato = c("Identificativo del provino", "Gruppo di provenienza",
                  "Punto di raccolta", "Massa del provino", "Volume del provino",
                  "Classe qualitativa ordinata"),
  unita = c("identificativo", "categoria", "identificativo", "g", "cm^3", "categoria"))
print(dizionario)
stopifnot(setequal(dizionario$campo, names(d)))

Il controllo assicura che tutte le colonne originali siano documentate. L’unità ‘categoria’ evita di presentare una classe come una misura fisica; la descrizione della stazione chiarisce il livello superiore a cui appartengono i provini.

2. Registrare trasformazioni e decisioni

Un registro deve identificare la riga, il campo, il valore originario e la scelta compiuta. Conserviamo questi elementi prima di modificare la copia, così la spiegazione rimane verificabile e non dipende dalla memoria dell’autore.

R · codice commentato
registro <- data.frame(id = c("C02", "C04"), campo = c("volume_cm3", "massa_g"),
                        originale = c(d$volume_cm3[d$id == "C02"], d$massa_g[d$id == "C04"]),
                        introdotto = c("0", "NA"),
                        motivo = "Anomalia introdotta per esercitazione",
                        decisione = "Conservare riga; densita non calcolabile")
d$volume_cm3[d$id == "C02"] <- 0
d$massa_g[d$id == "C04"] <- NA_real_
print(registro)
stopifnot(all(registro$id %in% d$id))

Lettura del risultato

La decisione riguarda l’utilizzo della densità, non l’esistenza del provino. Il registro distingue un’anomalia costruita da un errore rilevato nel file originale e conserva il valore necessario per ripristinare la copia.

3. Salvare insieme dati e descrizioni

Aggiungiamo un indicatore utilizzabile e salviamo tre file collegati. Una rilettura del registro controlla le chiavi: il pacchetto resta interpretabile soltanto se documentazione e tabella fanno riferimento agli stessi provini.

R · codice commentato
d$utilizzabile <- is.finite(d$massa_g) & d$massa_g > 0 &
                  is.finite(d$volume_cm3) & d$volume_cm3 > 0
write.csv(d, percorso_risultati("provini_con_audit.csv"), row.names = FALSE)

file_registro <- percorso_risultati("registro_decisioni.csv")

verifica <- read.csv(file_registro, stringsAsFactors = FALSE)
stopifnot(identical(verifica$id, registro$id))
print(table(d$utilizzabile))

Lettura del risultato

I tre file hanno funzioni diverse: valori e indicatori, significato delle colonne, storia delle decisioni. Separarli rende il materiale leggibile senza ripetere lunghe note in ogni riga del dataset.

Variante svolta

Ripristinare in una nuova copia i due valori usando il registro.

R · codice commentato
ripristinato <- d
for (i in seq_len(nrow(registro))) {
  riga <- match(registro$id[i], ripristinato$id)
  ripristinato[riga, registro$campo[i]] <- registro$originale[i]
}
print(ripristinato[ripristinato$id %in% registro$id, c("id", "massa_g", "volume_cm3")])
stopifnot(all(is.finite(ripristinato$massa_g)), all(ripristinato$volume_cm3 > 0))

La ricostruzione mostra il valore pratico del registro. Gli indicatori derivati andrebbero ricalcolati dopo il ripristino: conservare un vecchio flag accanto a misure aggiornate produrrebbe una descrizione incoerente.

Errore da riconoscere

Annotare soltanto ‘dati puliti’ nasconde criteri e trasformazioni. Una decisione leggibile nomina la riga interessata, la regola applicata e l’effetto sul calcolo successivo.

Risposta alla domanda

Metadati e registro rendono verificabile la relazione fra tabella ricevuta e tabella analizzata. La documentazione deve aggiornarsi insieme ai dati e includere anche le variabili derivate aggiunte in seguito.
