1. Costruire tabelle autosufficienti

Una tabella esportata deve conservare gli identificativi e rendere riconoscibile l’unità. Prepariamo una tabella per provino e una per affioramento: separarle evita di mescolare misure individuali e sintesi con unità di osservazione diversa.

R · codice commentato
# Ogni esecuzione riparte dal CSV condiviso, senza modificare il file.
d <- carica_dati("campioni_modulo1.csv", stringsAsFactors = FALSE)
stopifnot(nrow(d) == 24L, !anyDuplicated(d$id))

stopifnot(all(is.finite(d$massa_g)), all(d$massa_g > 0),
          all(is.finite(d$volume_cm3)), all(d$volume_cm3 > 0))
d$densita_g_cm3 <- d$massa_g / d$volume_cm3

individuali <- d[c("id", "affioramento", "stazione", "densita_g_cm3")]
medie <- aggregate(densita_g_cm3 ~ affioramento, data = d, FUN = mean)
conteggi <- as.data.frame(table(d$affioramento), stringsAsFactors = FALSE)
names(conteggi) <- c("affioramento", "n")
riassunto <- merge(medie, conteggi, by = "affioramento", sort = TRUE)
print(riassunto)
Risultato dell’esecuzione
affioramento densita_g_cm3  n
1            A       2.64750 12
2            B       2.55083 12

Lettura del risultato

Il nome della colonna distingue una densità da una massa o da un volume. La numerosità chiarisce su quante osservazioni si basa ogni media. Gli ID individuali rendono possibile risalire dai risultati ai dati originali.

2. Esportare e verificare il ritorno

Scriviamo file separati e rileggiamo quello individuale. La verifica riguarda sia le chiavi sia i numeri: un file esistente potrebbe comunque avere colonne indesiderate, righe perse o valori alterati dal formato di esportazione.

R · codice commentato
file_ind <- percorso_risultati("densita_provini.csv")
file_med <- percorso_risultati("medie_affioramenti.csv")
write.csv(individuali, file_ind, row.names = FALSE)
write.csv(riassunto, file_med, row.names = FALSE)
riletto <- read.csv(file_ind, stringsAsFactors = FALSE)
stopifnot(identical(riletto$id, individuali$id))
stopifnot(isTRUE(all.equal(riletto$densita_g_cm3, individuali$densita_g_cm3)))
print(head(riletto, 3))

Lettura del risultato

row.names = FALSE evita di aggiungere una colonna con la numerazione della stampa R. Il controllo numerico usa una tolleranza adeguata; l’identificativo deve invece corrispondere esattamente, nello stesso ordine.

3. Accompagnare il numero con una frase verificabile

Una nota leggibile deve indicare formula, verso della differenza e ambito del risultato. Costruiamo la frase dal valore calcolato, così testo e tabella non rischiano di divergere dopo una nuova esecuzione.

R · codice commentato
media_nominata <- setNames(riassunto$densita_g_cm3, riassunto$affioramento)
delta <- unname(media_nominata["B"] - media_nominata["A"])
nota <- c("Dati sintetici: 24 provini in sei stazioni di due affioramenti.",
          "Formula: densita = massa_g / volume_cm3; unita: g/cm^3.",
          sprintf("Differenza fra medie, B meno A: %.4f g/cm^3.", delta),
          "Confronto descrittivo; nessuna conclusione causale o generalizzazione automatica.")
writeLines(nota, percorso_risultati("nota_metodologica.txt"), useBytes = TRUE)
cat(paste(nota, collapse = "
"), "
")

Lettura del risultato

La frase riporta il numero effettivo senza attribuirgli un significato inferenziale non calcolato. La nota permette di leggere il risultato anche fuori dal notebook, dove non sarebbero disponibili tutti i passaggi precedenti.

La somma riconcilia tabella individuale e tabella aggregata. È un controllo utile quando filtri o gruppi cambiano: il lettore deve sapere se tutte le osservazioni esportate contribuiscono alla sintesi.

Errore da riconoscere

Salvare soltanto un numero separa il risultato dalla domanda. Identificativi, unità, formula, numerosità e ambito sono parte della consegna, non dettagli lasciati alla memoria di chi ha eseguito il codice.

Risposta alla domanda

I file esportati sono leggibili e verificati mediante rilettura. La nota spiega che cosa è stato calcolato e quali conclusioni il procedimento non ha ancora affrontato.
